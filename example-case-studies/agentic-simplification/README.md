# Agentic Simplification Case Studies

These case studies record designs whose Architecture Pressure dropped sharply
because a story initially framed as bespoke application software was delivered
agentically or as a thin hybrid. The normative rules live in
[agentic_delivery_foundations.md](../../requirements/agentic_delivery_foundations.md),
[agentic_pm_user_story_preflight.md](../../requirements/agentic_pm_user_story_preflight.md),
and
[agentic_architecture_pressure_scoring.md](../../requirements/agentic_architecture_pressure_scoring.md).

When recording new cases here (or in `case-studies/local/`), capture:

- the story or design as first written, and its naive software Architecture
  Pressure (`1-5`);
- the delivery mode it resolved to (`Software`, `Hybrid`, or `Agentic`), and the
  software remainder (if any);
- which *"still needs software"* signal justified any retained software
  remainder;
- the instruction/playbook surface carrying the agentic behavior;
- operational evidence that the simplified delivery held up in real use (or,
  equally valuable, a case where an agentic simplification failed and earned
  graduating into application software).

See the worked delivery-mode examples in
[agentic_delivery_foundations.md](../../requirements/agentic_delivery_foundations.md)
while new full-length post-mortems are collected.
